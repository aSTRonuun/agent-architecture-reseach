Large language models are usually integrated into web applications through
direct calls to the provider's software development kit scattered across the
business logic, coupling the application to a single vendor. An alternative is
to interpose an intermediate architectural layer, here called a
\textit{harness}, to centralize provider communication, tool execution, state
management, failure handling, and event logging. Existing literature proposes
such architectures and discusses their trade-offs qualitatively, without
controlled measurements. This work designs and experimentally evaluates this
layer, weighing provider replacement cost against its energy overhead by
comparing two functionally equivalent versions of the same web application: one
integrated through the harness and one integrated directly. Replacement cost is
quantified through structural code metrics and preserved use cases when
switching between Anthropic and OpenAI, in scenarios without and with
strict-schema structured outputs. The energy effect is evaluated using GPU
hardware telemetry (NVML) on simple and agentic requests to the open Qwen3.6 27B
model hosted on an institutional server, combined with an upper bound for direct
CPU cost on the application machine. A pre-registered decision criterion will
characterize when the achieved decoupling outweighs the energy overhead,
providing quantitative evidence to support architectural decisions.
